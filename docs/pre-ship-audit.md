# Nextstepuni — Pre-Ship Code Audit

**Date:** 2026-06-01  
**Method:** 9-dimension multi-agent review, every finding adversarially verified against real code (blockers/highs by 3-verifier vote). 80 agents, ~3.9M tokens, ~92 min.  
**Verdict: 🔴 DO-NOT-SHIP** — 4 independent blockers.

**Confirmed:** 34 findings (4 blocker · 12 high · 6 medium · 12 low). 2 candidate findings refuted by verification.

## Verdict rationale

Four independent blockers each independently force do-not-ship. CRASHES ON COMMON PATHS: (1) JourneyView crashes on mount with `ReferenceError: useEffect is not defined` (missing import, components/journey/JourneyView.tsx:6/131) — the Journey/Island gamification view white-screens on every open; (2) the GC Broadcast modal crashes with `ReferenceError: broadcastYearGroup is not defined` (typo for the plural Set state, GCOverview.tsx:870) on first click, taking down the GC-to-students messaging feature. Both ship because CI gates only on `npm run build` (esbuild, no type-check), so tsc's TS2304/TS2552 never block. BROKEN CORE DATA PATH: (3) the `/progress/{uid}/sessions` subcollection has no Firestore rule and falls through to default-deny, so every user's own study-session save AND reload is permission-denied — the entire study-session/streak/mastery/insights/quests pipeline silently shows nothing for the data's own owner. MINORS' PII WITHOUT LAWFUL BASIS: (4) registration writes a minor's real name + identifiable school to Firestore with no consent capture, no privacy policy/terms link anywhere, no age gate, and no parental-consent mechanism; the DPIA's assumed basis is unevidenced in code and Art. 13 transparency is entirely absent — collecting children's PII in this state is a GDPR blocker for a product about to ship. Beyond the blockers there is a large high/medium tail (over-broad same-school read of minors' real names on /users, gcFlags feature non-functional, three dead-legacy-`studySessions`-array runtime regressions, stale native bundles, ungated service worker in the native WebView, heavy eager bundle weight, a server-side reachable critical protobufjs in Cloud Functions, and no data-subject-rights/cascade-delete). The tsc 'never' error cluster (R3F JSX augmentation) is not itself a runtime bug but it is the cross-cutting enabler that buried all three runtime-crash type errors. None of the four blockers is hard to fix (three are one-to-two-line code/rules changes; the consent blocker is the only substantial one), so a fast remediation pass plus a rules redeploy gets this to ship-with-fixes territory.

## Ship blockers

### B1. JourneyView crashes on mount — useEffect used but not imported (ReferenceError)
- **File:** components/journey/JourneyView.tsx (line 6 import; line 131 usage)
- **Why it blocks:** The hook runs unconditionally on every mount of the lazy-loaded Journey/Island view (AppRouter.tsx:422), throwing ReferenceError: useEffect is not defined and white-screening a core gamification feature on every visit. esbuild ships the bare reference; CI build does not type-check so TS2304 never blocks.

### B2. GC Broadcast modal crashes — undefined broadcastYearGroup (typo for plural Set state broadcastYearGroups)
- **File:** components/gc/GCOverview.tsx (line 870; state at line 181)
- **Why it blocks:** When a GC opens Broadcast Message, line 870 evaluates the undefined identifier broadcastYearGroup during render (broadcastCurriculum defaults to 'all' so the || short-circuits into it), throwing ReferenceError and crashing the GC-to-students messaging feature on first click. Ships because the build does not run tsc (would be TS2552).

### B3. progress/{uid}/sessions subcollection has no Firestore rule — default-deny breaks every user's own study-session save AND load
- **File:** firestore.rules (match /progress/{userId} lines 65-101; default deny 286-288)
- **Why it blocks:** Firestore rules are non-hierarchical, so the sessions subcollection written/read at useStudySession.ts:288-289 and ProgressContext.tsx:230 falls through to allow read,write:if false. Every session write is permission-denied and never durably persisted; fresh-load reads are denied, so studySessions is always empty and the entire study-session/streak/mastery/insights/quests pipeline silently shows nothing on the owner's own most-common path. Errors are swallowed by .catch(console.error).

### B4. No consent flow, no privacy policy, no age gate before a minor's name + school are written to Firestore
- **File:** components/LoginPage.tsx (handleRegisterSubmit 407-432; register step 1 form 739-770)
- **Why it blocks:** A child self-registers and has their real name + identifiable school written to a cloud DB with no transparency notice (GDPR Art. 13, required under any basis), no consent capture, no age gate, and no parental-consent mechanism. The DPIA's assumed lawful basis (school-enrolment / parental consent) is neither evidenced nor surfaced in the app, and ALEX_TO_CONFIRM Q16 leaves the consent mechanism unanswered. Shipping collects minors' PII with no demonstrable lawful basis.
